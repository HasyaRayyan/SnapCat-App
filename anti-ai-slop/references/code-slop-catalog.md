# Code Slop Catalog & Remedies

A reference catalog of mechanical anti-patterns frequently generated by AI models in codebases, accompanied by exact root causes, smells, and human-grade remedies.

---

## 1. Superficial & Restating Comments

### Smell
Comments that literally translate the code into English words without providing historical rationale, architectural context, or edge-case explanations.

```typescript
// BAD: Restating the obvious
// Set active state to true
setIsActive(true);

// Loop through each item in the list
for (const item of items) {
  // Call processItem function with item
  processItem(item);
}

// User repository class
export class UserRepository {
  // Constructor
  constructor(private db: Database) {}
}
```

### Remedy
Delete them completely. Code should be clean enough to be self-explanatory. Keep comments **only** when answering "Why is this done this way instead of the obvious way?".

```typescript
// GOOD: Zero fluff, self-describing code
setIsActive(true);

for (const item of items) {
  processItem(item);
}

export class UserRepository {
  constructor(private db: Database) {}
}

// ACCEPTABLE COMMENT: Explains non-obvious domain constraint
// SQLite locks the database during WAL checkpointing; batching at 250 prevents timeout in CI.
```

## 2. Paranoid Cargo-Cult Defensive Guards

### Smell
Sprinkling dozens of null/undefined/type checks on internal variables that the language compiler, ORM, or framework already guarantees are valid.

```typescript
// BAD: AI writes paranoid guards everywhere
function calculateTotal(price: number, quantity: number): number {
  if (price === null || price === undefined || typeof price !== 'number') {
    throw new Error('Price is required and must be a number');
  }
  if (quantity === null || quantity === undefined || typeof quantity !== 'number') {
    throw new Error('Quantity is required and must be a number');
  }
  return price * quantity;
}
```

### Remedy
Trust your static types at internal boundaries. Validate at external network/input boundaries (e.g. Zod, FormRequest), then write direct business logic internally.

```typescript
// GOOD: Let TypeScript or static typing do its job
function calculateTotal(price: number, quantity: number): number {
  return price * quantity;
}
```

> **Warning (Chesterton's Fence):** Do not delete guards that protect against *external hazards* (e.g., parsing untrusted webhook payloads, handling nullable database foreign keys, or protecting against browser localStorage quota exhaustion). Only strip local redundant guards.

## 3. Premature & Faux-Enterprise Over-Abstraction

### Smell
Creating factories, single-implementation interfaces, abstract base classes, and 5-layer indirection for straightforward 10-line tasks.

```typescript
// BAD: AI creating enterprise architecture for a simple greeting
interface IGreeterService {
  greet(name: string): string;
}

class GreeterServiceImpl implements IGreeterService {
  greet(name: string): string {
    return `Hello, ${name}!`;
  }
}

class GreeterFactory {
  public static createGreeter(): IGreeterService {
    return new GreeterServiceImpl();
  }
}

// In consumer:
const greeter = GreeterFactory.createGreeter();
greeter.greet('Alice');
```

### Remedy
Use plain functions. Three similar lines of code are better than a premature, single-consumer abstraction.

```typescript
// GOOD: Plain function
export function greet(name: string): string {
  return `Hello, ${name}!`;
}
```

## 4. Phantom Error Handling & Stack Squashing

### Smell
Catching errors only to re-throw identical errors, wrap them in generic errors that destroy stack traces, or silently return `null` and hide production bugs.

```typescript
// BAD: Catch-and-rethrow (pointless)
try {
  await fetchUserData(userId);
} catch (error) {
  logger.error(error);
  throw error; // Just clutters code without adding recovery
}

// WORSE: Squashing the stack trace
try {
  await db.query(sql);
} catch (error: any) {
  throw new Error(`Failed to query database: ${error.message}`); // Original callsite and stack lost!
}

// WORST: Silent swallow
try {
  doCriticalSync();
} catch (e) {
  // Silent fail - impossible to debug in production
}
```

### Remedy
Let errors naturally propagate to top-level error boundaries or middleware. If adding context, use `cause`:

```typescript
// GOOD: Let it bubble up naturally
await fetchUserData(userId);

// GOOD: If adding context, preserve cause
try {
  await db.query(sql);
} catch (error) {
  throw new Error(`User query failed for ${userId}`, { cause: error });
}
```

## 5. Re-implementing the Standard Library

### Smell
AI often generates 10-line nested imperative loops to perform operations that the standard library accomplishes natively and more efficiently.

```php
// BAD: Hand-rolled loop in PHP
$activeUserNames = [];
foreach ($users as $user) {
    if ($user->isActive == true) {
        $activeUserNames[] = $user->name;
    }
}
```

```php
// GOOD: Idiomatic collection or array function
$activeUserNames = $users->where('isActive', true)->pluck('name');
```

```javascript
// BAD: Hand-rolled unique array in JavaScript
const unique = [];
for (let i = 0; i < arr.length; i++) {
  if (unique.indexOf(arr[i]) === -1) {
    unique.push(arr[i]);
  }
}

// GOOD: Native Set
const unique = [...new Set(arr)];
```

## 6. Hand-Maintained Platform Guarantees

### Smell
Writing manual retry logic around an HTTP client that already has exponential backoff configured, or writing manual in-memory cache expiration when the database/ORM layer already handles query caching.

### Remedy
Identify the owner of the guarantee. If Axios, Guzzle, or Laravel HTTP client already handles retry with backoff, eliminate the custom `while (attempts < 3)` wrapper.

---

## 7. Lazy Stubs & Hallucinated Artifacts

### Smell
- Leaving comments like `// ... rest of implementation remains unchanged` inside edited files.
- Calling external library functions with options that do not exist in the installed library version.
- Adding unneeded dependencies to `package.json` or `composer.json` when standard utilities suffice.

### Remedy
- Never submit truncated code with `// ... continue pattern`. Provide the complete, working code.
- Check installed packages and API signatures before calling them.
